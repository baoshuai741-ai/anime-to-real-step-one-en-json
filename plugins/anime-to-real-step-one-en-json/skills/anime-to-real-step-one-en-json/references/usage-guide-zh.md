# 漫画转真人·第一步（中文描述 JSON）使用说明

## 作用与边界

本插件只执行第一步：读取当前参考图，先建立视觉事实层，再在不推翻事实的前提下写出真人化解释和角色 DNA。它不生成图片，不执行第二步。

权限链固定为：当前原图 > 视觉事实 > 真人化解释 > 最终生成。后级只能翻译前级，不能覆盖前级。

## 输入要求

- 至少提供一张当前消息中的动漫、漫画、插画或虚拟角色参考图。
- 默认只认当前上传内容，不读取旧图、旧 JSON、角色百科或历史对话。
- 多图时应明确每张图的职责，例如“图 1 控制脸和头发，图 2 只控制服装”。未分配职责的图不得自动混合。
- 图片中看不见、被遮挡、出画或分辨率不足的内容不会被补全。

## 操作步骤

1. 在新任务中上传当前参考图。
2. 明确调用 `$anime-to-real-step-one-en-json`，必要时说明多图职责。
3. 插件返回且只返回一个有效 JSON 对象。
4. 检查 `evidence_confidence`、`visual_facts`、`anime_rendering_artifacts` 和 `uncertain_or_occluded` 是否准确。
5. 确认后，把当前原图和完整 JSON 一起交给第二步。不要只给 JSON，也不要把第一步输出当成最终生图提示词直接生成。

## 关键字段

### 稳定性与衣服质感更新

`character_conversion.execution_summary` 是新增可选索引，包含 `priority_anchors`、`allowed_translations`、`case_rejections`、`unresolved_conflicts`。每项用 `source_paths` 指向已有权威字段，同时保存简短 `instruction` 和原置信度；不形成另一份角色定义，旧 JSON 没有它仍可用。

同一属性先在 `visual_facts` 记录，其他设计字段只作一致展开或索引；真人面部以 `live_action_identity_lock` 为准，表情另锁。输出前消除转述冲突，真正歧义仍留空。

固定英文 `negative_prompt` 列表保留兼容，但不再要求第二步原样全部发送：大眼特征、弯曲关节、合理的光泽/塑料/橡胶衣物、正常肤色差异与失焦均不能被宽泛负面词误删。

服装款式、颜色、结构、图案与穿法留在 `costume`；`capture_conditioned_realism.material_response_map` 新增逐衣物的光学类别、结构锁、褶皱受力、纹理尺度/方向、边缘厚度/接触与反射/透射描述。材料名称没有证据则留空，用可见响应类别约束，不猜“棉/丝/皮”。不添加看不见的缝线、内衬、织纹图案、磨损或透明度。第一步仍只分析当前原画，不读取真实人物照片或摄影基准。

- `authority_chain`：固定权限顺序，后级不得推翻前级事实。
- `evidence_confidence.clearly_visible`：原图直接可见事实。
- `evidence_confidence.high_confidence_inference`：有明确画面依据但未完全展示的高可信判断，应写明依据。
- `evidence_confidence.cannot_confirm`：无法确认的内容，禁止补全。
- `visual_facts`：按脸、眼睛、头发、身体、服装、生物结构、镜头和环境整理的事实档案。
- `anime_rendering_artifacts`：二维高光、块面阴影、描边等绘画语言；不得直接变成染发、皮肤斑痕、硬质发块或服装接缝。
- `uncertain_or_occluded`：未知、遮挡、裁切、歧义和禁止推断项目。
- `character_dna`：从事实层提炼的身份关键特征。
- `immutable_anchor`：后续步骤不得改动的、有证据支持的设计锚点。
- `medium_translation_analysis`：在不新增视觉事实的前提下，把角色设计、二维画法、应保留内容、需最小现实化内容、可确认的纯绘画痕迹和现实等价物分开记录。
- `facial_anatomy_mapping`：先记录整脸拓扑与姿态透视影响，再建立真人颅面基础、映射 Face DNA、记录最小修正并分别锁定稳定身份结构和当前镜头表情。
- `realism_translation_rules`：如何把已确认二维设计转译为真实解剖、真实材质和真实光学表现。
- `realism_foundation`：集中保存角色无关的真人面部基础、皮肤结构与光学、Hair Intent First、身体生物力学和结构光规则；不得把这些通用规则散落成新的顶层大结构。`character.appearance.skin.avoid` 与 `hair.avoid` 只镜像简短失败标签，不得另建一套转译规则或新增源图事实。
- `capture_conditioned_realism`：把已确认的设计和构图转成受主体尺寸、焦平面、景深、运动、曝光与图像质量约束的逐区域执行规格，并为第二步提供生成后视觉验收标准。它不是新的事实来源，不能把未知内容改写成肯定信息。
- `high_risk_translation_items`：最容易被错误正常化或错误物理化的项目，例如高黑眼球比例、强眼球反射、异常发型轮廓、二维发丝高光、极端姿态和非人结构。
- `visual_translation_rules`：为兼容旧工作流保留；内容应与新的真人化解释一致，不得写入新的源事实。
- `negative_prompt`：固定英文负面词列表；其他视觉描述使用中文。

## 新增媒介转译分析层

`character_conversion.medium_translation_analysis` 是向后兼容的新增对象，含 `character_dna`、`medium_dna`、`preserve_features`、`translate_features`、`discard_features`、`real_world_equivalents` 六个数组。先依据 `visual_facts` 和置信度记录角色设计与二维画法，再区分必须保留、需要最小现实化、只应去除的绘画痕迹。每条中文描述都应写明作用区域、可见依据或画法证据、置信度、需保留的设计含义和处理方式，并可追溯到当前图片及多图时的 `reference_roles`；不能只写“赛璐璐风”“厚涂风”等宽泛风格名称。未知或遮挡内容仍放在原有不确定字段，不能进入肯定式转换规则。旧字段与固定英文 `negative_prompt` 保持原样。

## 跨画风稳定化

无论输入是赛璐璐、厚涂、黑白漫画、稀疏线稿、Q 版、半写实插画还是 3D／CG 感渲染，第一步都使用同一套证据标准，不为某一种画风另选角色解释。分析时分别检查：

- 描边、排线和图形分隔；
- 关系结构与被画风放大的绝对尺寸；
- 明暗、色块阴影和绘制高光；
- 局部固有色与全局调色、辉光；
- 可见材质结构与被省略、简化或笔触化的表面细节；
- 姿势、构图、透视、光线方向与非摄影投影或渲染习惯。

先保留字面可见事实，再把角色设计含义与表现它的画法分开。平涂不证明材质是平的，省略线条不证明结构不存在，厚涂笔触不等于真实表面纹理，3D／CG 阴影也不自动成为真人摄影布光。信息越少，置信度越低；不能因此调用通用美人脸、默认材质、默认镜头或默认灯光补全。无法分离设计和画法时，应记录歧义并保守保留，不得直接丢弃。

顶层 `style` 与 `quality` 只定义真人摄影目标，不覆盖原图的具体镜头和光线。`camera`、`lighting` 中只有当前图可支持的内容才能写入；原图无法确定的摄影属性保持空值，由第二步使用中性真实相机行为补足，不固定手机焦段、影棚光、电影机或时尚写真风格。

## 摄影尺度门控与验收层

`character_conversion.capture_conditioned_realism` 是向后兼容的可选对象，所有子数组均须保留；没有证据时使用 `[]`。它不会改变 14 个顶层键，也不会替代 `visual_facts`、`facial_anatomy_mapping` 或现有权限链。

每个已填充条目至少使用以下英文键并填写中文值：`region`、`source_evidence`、`confidence`、`resolvable_scale`、`physical_behavior`、`must_preserve`、`must_not_invent`、`failure_signs`。其中 `resolvable_scale` 必须先回答最终镜头只能可靠呈现宏观结构、中尺度差异，还是能够呈现微细节。

- `source_capture_limitations`：记录裁切、遮挡、主体像素占比不足、画法省略、绘制模糊或压缩式痕迹；不能猜测 EXIF、焦距、光圈、ISO 或相机型号。
- `resolution_visibility_gate`：控制毛孔、绒毛、细纹、单根发丝、织物纤维、微小划痕和颗粒是否有资格出现。远景、失焦、运动或低像素覆盖时应省略这些细节，而不是放大或锐化。
- `skin_region_map`：逐区域写相对微纹理、粗糙度、油脂、局部色差、高光和阴影过渡。SSS 只作为受光支持的低频光色过渡，禁止全脸发光、整体发红或蜡状半透明。
- `hair_multiscale_map`：明确整体轮廓与重量、不均匀中尺度发组、发根密度和焦点／轮廓处少量单丝。最低限度的边缘随机性不等于新增发型，但不得新增风、湿发、运动或大量碎发。
- `face_physical_structure_map`：把现有面部映射具体化为眼球眼睑、鼻梁鼻尖鼻翼、人中、嘴唇干湿边界、口周软组织、颧面、下颌、耳部和有证据支持的不对称；不能创造新身份。
- `body_soft_tissue_map`：只记录可见体块、关节支撑、承重、压缩、拉伸和接触。
- `material_response_map`：逐材质记录相对厚度、边缘、缝线或构造、受力方向、褶皱原因、垂坠、透光和反射宽度。
- `camera_imaging_pipeline`：只写原图支持的透视、焦点、锐度层级、空间深度、曝光、混合光／白平衡、高光与黑位、运动模糊及可见成像痕迹；不能把内部摄影选择写成源图事实。
- `environment_light_transport`：连接环境光、反射面与人物上的色溢出、二次反射、接触阴影和遮挡。
- `negative_prompt_scope`：限定宽泛固定负面词只拒绝生成错误。物理可信的焦外、运动模糊、轻微噪点、压缩、局部柔和和自然肤色差异不属于低清、模糊或肤色斑块。
- `body_proportion_override_gate`：保留 `9 head body proportion` 的兼容目标，但只有可靠全身证据成立且无需改姿势、机位、裁切、重心、接触、遮挡或未知结构时才允许第二步表现。
- `visual_acceptance_criteria`：为同一张图列出脸部身份、皮肤分区、头发层级、人体受力、材质分离、镜头锐度和环境耦合的 PASS／FAIL 标准。

## 三条底层转译顺序

### 面部：Face Foundation First

二维绝对尺寸先作为源图证据保留，不能直接当成最终真人几何。进入真人化解释后，先建立与表观年龄一致的真人头骨与颅面、眼眶、眼球眼睑、鼻骨鼻软骨、颧骨、上颌下颌、面部肌肉、脂肪与软组织基础，再把五官类型、方向、相对趋势、视觉权重、身份语义和可见不对称映射进去。人体结构决定可行范围，源图 Face DNA 决定最接近哪个身份结果；审美平均值、黄金比例、网红脸和真实人物模板均不能覆盖。

### 皮肤：Skin Structure First

真实感来自皮肤结构、区域差异和光学，而不是磨皮后叠加统一毛孔。只有主体尺寸、焦点和光线允许时，最终皮肤才呈现自然细小绒毛、按部位变化的毛孔与微纹理；其他情况下主要依靠局部粗糙度、油脂、肤色、体积阴影和高光变化建立真实感。皮下血色与血管影响必须克制，亚表面散射只表现为低频光色过渡。禁止统一毛孔、统一锐化、塑料皮、蜡像皮、瓷器皮、磨皮滤镜、整体发红和无依据的明显血管；禁止的是无依据的大面积突兀色块、重复贴图或脏污，不得因此清除自然区域肤色差异。

### 头发：Hair Intent First

先读二维头发想表达的轮廓、长度、分缝、刘海、主流向、体积层级、关键脸侧发束、柔顺、飘逸、层次和空气感，再按“整体轮廓与重量—不均匀中尺度自然发组—焦点和轮廓处少量单丝”实现真实头发生长与重力。大量走向线、过多分束、条带边界、丝带状高光和密集碎发可能只是画法，不得逐条变成真实发束；也不得因过度合并而成为一整片光滑假发面。若无法确认某条线是设计还是画法，应记录为歧义，不能直接丢弃。

## 何时使用第一步与第二步

第一步适用于：新参考图首次进入流程、参考图更换、角色设计发生变化、多图职责重新分配，或旧 JSON 的视觉读取可能有误。

第二步只在第一步 JSON 已检查通过后执行。第二步必须同时接收当前原图和完整第一步 JSON，负责生成真人图；它无权改写视觉事实或擅自新增删除服装、配饰、生物结构。

## 常见错误

- 把“银白块面高光”写成白色染发：应放入 `anime_rendering_artifacts`，真实头发只转译为自然发丝反射。
- 把二维走向线、条带式分束和密集碎发逐条生成：应保留主流向、体积层级与柔顺飘逸意图，只弱化已确认属于画法的过度分割。
- 把阴影、描边或噪点写成痣、伤疤、肤色斑块：没有直接证据时放入歧义或无法确认。
- 用统一毛孔、全脸锐化或整体泛红制造“真实皮肤”：应改为按部位变化的绒毛、微纹理、粗糙度、油脂、皮下血色、极轻微合理血管影响和随受光角度变化的反射。
- 无视镜头尺度，在远景脸部生成清晰毛孔、全头单根发丝或衣物纤维：应先执行 `resolution_visibility_gate`，只保留当前焦点和像素覆盖能够解析的层级。
- 把正常焦外、运动模糊、轻微噪点或自然肤色差异当成 `blurry face`、`low detail`、`skin blotches`：应通过 `negative_prompt_scope` 将这些负面词限制为焦平面内的结构涂抹、重复贴图和无依据突兀色块。
- 自动缩小高虹膜/高黑眼球比例：先作为视觉事实和角色 DNA 记录，再做物理可信的真人眼球转译。
- 先按二维绝对尺寸摆好五官，再补真人纹理：顺序错误；必须先建立真人颅面与软组织基础，再映射 Face DNA，二维夸张尺寸只保留为证据和最小修正记录。
- 为了真人比例改变脸型、眼距、耳朵、发型轮廓或动作意图：不允许；只有用户授权的固定九头身目标是比例例外，并须保留源比例记录。
- 猜测背面服装、鞋底、被头发挡住的耳朵或手：不允许补全。
- 把第一步输出直接当成第二步结果：第一步不生成图片。
- 使用旧图、旧 JSON 或角色设定补充当前图：不允许，除非用户在当前消息明确提供并分配职责。

## 备份与恢复

升级前保留当前插件目录副本或记录已安装的 Git 提交。需要回滚时，从备份或先前提交恢复对应插件，并通过原安装方式重新安装。保留备份，在新任务中验证调用。

结构验证、安装验证和真实图片输出测试是三个不同层级；前两者通过不代表真实生成效果已通过。
