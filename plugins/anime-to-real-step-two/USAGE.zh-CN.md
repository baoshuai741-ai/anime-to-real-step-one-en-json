# 漫画转真人·第二步使用说明

## 输入与输出

第一步只分析当前原画，并返回完整、有效的 JSON。审阅并确认 JSON 后，在新的第二步请求中同时附上同一张原画和已确认的第一步 JSON，明确要求生成第二步真人图。第二步不得从早先聊天补取图像或 JSON；任何一项缺失都需重新提供。生成前会先检查当前 Step One 的 14 个顶层键及 `character_conversion` 核心层；空字符串或空数组代表主动保持未知，字段缺失则不是未知。若核心字段缺失且没有可识别旧版等价字段，第二步会指出缺失并停止，而不是静默只看原图自由发挥。若只要求提示词，第二步返回审核后的生成提示词，并把图像验证标为待生成。若明确要求生成，第二步在内部执行“生成—视觉验收—最多两次局部修正调用”闭环：全部必测项通过才输出 `PASS` 结果；仍失败则报告失败项，不把成功出图当作成功写实。第三步只在用户另行明确要求时开始。

## 规则优先级

第二步必须先读取内置 `skills/anime-to-real-step-two/references/REAL_PHOTO_REFERENCE.json`，使用其中第二步的权限定义。它与第三步保持同版，只提供物理/摄影规则，不借用实拍人物或衣服；原画仍是角色视觉权威，第一步 JSON 仍是角色文字权威。基准损坏或缺失时停止。具体以技能入口的权限与执行规则为准。

1. 当前图片职责、原画可见事实与证据置信度
2. 未知、遮挡、裁切和禁止推断边界
3. 角色 DNA、不可变锚点与应保留设计
4. 真人身份结构锁与当前镜头表情锁
5. 原画构图、姿势、镜头、光线、颜色、环境与材质关系
6. 最小现实转译与现实等价物
7. 仅在当前构图可可靠执行时采用的九头身目标
8. 真实人体、皮肤、头发、服装和摄影物理
9. 当前角色专属禁止项
10. 固定通用负面约束与 Anti-AI 抑制
11. 模型默认审美（最低）

已确认的第一步 JSON 是角色外观与生成约束的唯一结构化权威；当前原画用于核对可见事实。若两者冲突，先指出冲突，不擅自改写或猜测。固定 `9 head body proportion` 是用户明确指定的全身设计目标，但只在当前构图可靠显示足够身体、且无需改姿势、机位、裁切、重心、接触或补全隐藏肢体时执行。近景、半身、跪坐、强透视或身体被遮挡时，不得为显示九头身而扩图、缩头、拉腿或改变构图。后层只能把前层确定的视觉信息转译为物理和摄影效果，不能改变角色、面部关系、服装、姿势、相机、背景或可见光影。遮挡、裁切和模糊区域保持未知；仅当前请求明确指定的字段可覆盖对应字段。

目标为受成像尺度约束的摄影物理表现；旧 JSON 中的 Extreme 等词不作为额外锐化、精修或美化命令。二维高光、描边和色块先判断其设计含义，再转成可信的光学或材质效果；不能机械地当作染发、发光、衣物图案或第二光源。不得用 surreal 或 surrealistic 描述目标效果。高分辨率不等于过度锐化。

## 当前主契约与旧版兼容

`capture_conditioned_realism` 和 `execution_summary` 都可在旧版 JSON 中缺失。摘要只是索引：核对其 `source_paths` 指向真实非空字段、置信度未升级后用于编译；没有摘要时按相同顺序从完整 JSON 编译。摘要冲突可回到权威字段重编译，原字段或原图/JSON 的未决冲突则停止生成。

完整读取但不盲目发送固定负面词表。按当前图限定“眼睛过大”“弯曲肢体”“塑料衣服”“模糊”等词的伪影含义，删除执行包中不适用或有冲突的通用词，以具体缺陷描述替代；不修改用户提交的 JSON。

当前版本以 Step One 实际输出为主契约：顶层 `character`、`hair`、`facial_features`、`costume`、`accessories`、`body`、`environment`、`camera`、`lighting` 与 `quality` 保存逐区域信息；`character_conversion` 内的来源／目标阶段、权限链、证据层、不确定项、虚构角色声明、角色 DNA、不可变锚点、媒介转译、面部映射和写实基础控制如何执行。新增的 `capture_conditioned_realism` 把已有证据转成受主体尺寸、焦平面、景深、运动、曝光和图像质量约束的逐区域材质、摄影与验收规格，但不是新的事实来源。虚构角色声明要求结果保持原创虚构身份，不得借演员、名人或真实人物替代真人映射。

第二步先保护 `character_dna`、`immutable_anchor` 和 `medium_translation_analysis.preserve_features`；仅将 `translate_features` 按 `real_world_equivalents` 作最小现实化；只禁止 `discard_features` 明确标注的纯画法以字面实体形式出现，不能连同其承载的发型、颜色、轮廓、服装结构或身份语义一起删除。`medium_dna` 是描边、排线、色块边界、厚涂笔触、绘制高光、重复发流线或 CG 式表现机制，不等于实体特征。

面部必须显式读取 `facial_anatomy_mapping`：先由整脸拓扑与姿态透视建立真人颅面基础，再执行最小修正、身份语义、真人身份结构锁和当前镜头表情锁，不能先摆放动漫五官再贴真人皮肤。

旧版顶层 `reference_authority`、`visual_facts`、`confidence_layer`、`anime_to_real_translation`、`photorealistic_target`、`generation_constraints` 仅在对应当前字段缺失时作为兼容别名。若新旧字段同时存在，当前主契约优先；明显冲突时停止并指出冲突，不拼接成第三种设计。

## 角色专属生成执行包

第二步在真正调用图像生成前，会把第一步中分散的信息压缩为仅供本次生成使用的内部执行包，而不是把完整 JSON 原样平铺给生成模型。执行包不是新的证据层，也不会修改第一步合同；每一项必须能回溯到当前原图或已批准 JSON。

执行包依次包含：

1. 通常 6–12 项最重要、最不能丢失的角色视觉 DNA；证据不足时不凑数
2. 真人面部身份结构与当前镜头表情锁
3. 姿势、机位、裁切、构图、环境和接触关系锁
4. 关键二维特征到现实结构或材质的一对一转译
5. 当前画面各类材质互不相同的物理响应
6. 原图摄影信息与未确认属性的中性摄影实现
7. 针对当前角色最容易发生的设计漂移所形成的专属禁止项
8. 经适用范围筛选、去重且不与角色冲突的通用伪影约束
9. 一句简洁的最终真人摄影锁

角色专属正向锚点必须先于负面词。固定通用负面词不能淹没发型、服装覆盖范围、特殊生物结构、配色、姿势或构图，也不能删除被原图支持的夸张但可现实转译的身份语义。

若 JSON 含 `capture_conditioned_realism`，执行包还必须吸收：微细节可见度上限、皮肤逐区域差异、头发宏观／中尺度／稀疏单丝层级、面部物理结构、身体软组织与接触、逐材质厚度和受力、相机成像链、环境光传输、固定负面词适用范围、九头身执行门槛及当前图片的 PASS／FAIL 标准。旧版 JSON 缺少该对象时继续兼容，但不得伪造这些信息。

## 跨画风稳定化

赛璐璐、厚涂、黑白漫画、稀疏线稿、Q 版、半写实与 3D／CG 感输入使用同一证据与映射顺序。平涂不证明材质是平的，省略线条不证明结构不存在，笔触不等于皮肤或布料纹理，CG 阴影也不自动成为真人摄影布光。信息不足时降低置信度并保持未知，不能调用通用美人脸、默认材质、默认镜头或默认灯光补全。无法区分设计与画法时保守保留，不直接丢弃。

## 摄影物理与材质

根据原画构图确定焦平面：重要可见特征清楚，前后景自然渐变失焦，近镜头手部或道具可略软但结构仍可辨；不得让全图同等锐利，也不得用夸张背景虚化抹掉原画场景。毛孔、绒毛、单根发丝、织物纤维和微小划痕只有在主体像素覆盖、焦点、景深、运动、曝光与图像质量共同允许时才解析；远景或焦外区域依靠体积、区域色差、材质高光和中尺度结构保持真实，不得强加微细节。高光平滑滚降并保留亮部材质，阴影有深度和可用层次但不做 HDR 式抬亮。皮肤、头发、布料、皮革、金属、羽毛等各有相应粗糙度、反射、厚度、边缘、受力与局部清晰度，禁止统一锐化、微对比和高光。人物还必须接收环境的色溢出、二次反射、接触阴影和遮挡，使人物与背景像同一次曝光而不是后期拼贴。可有轻微合理的颗粒、降噪、压缩、运动模糊、边缘柔化与局部解析差异，但不得借此新增身份痕迹。固定负面词 `low detail`、`low resolution`、`blurry face`、`blurry costume` 只拒绝焦平面内的结构涂抹、双影和生成崩坏；正常景深、焦外柔化和运动模糊不属于失败。原画不能确认具体摄影属性时，第二步可在内部选择与当前裁切、机位、透视、主体距离和环境相容的中性焦段行为、焦平面、景深、曝光和补光，作为生成实现而不是源事实；不得用同一套手机焦段、电影机、广播演播室、摄影棚或时尚写真模板覆盖所有图片。

## 生成后视觉验收

衣服采用独立六项验收：款式/穿法不变、主褶皱及受力连续、现有边缘厚度与叠层可信、纹理随形且尺度正确、高光/透射符合材料类别、焦内外细节合理。先结构与受力，再表面反光，最后才是能解析的纤维；不能把高清噪点、额外缝线、磨损或新增针织图案当质感。光泽面料并不天然是失败，原有塑料/橡胶服装也不能被统一哑光化。

结构失败（换脸、人体拓扑、服装设计、姿势/构图/场景错误）停止并报告 `STRUCTURAL_FAIL`，不交第三步补纹理。只有局部表面问题可在保留通过区域的前提下修复，最多两次局部编辑调用；无可靠局部能力则 `FAIL`，不自动整图重生成。每次修正都对照初次生成图和原画约束，不在失败图上继续累积修改。无法读取实际结果为 `UNVERIFIED`；不可见项记不适用，不能冒称已验证。

默认在图片后附面部、皮肤、头发、衣服、身体、镜头/背景的简短状态。只要图片时通过后可不附报告，但不能隐藏失败或未验证状态。提示词的区域限定不是像素蒙版，不保证零漂移。

每次实际生成后必须检查生成图本身，而不是只检查提示词。必测项包括：

1. 面部为有具体身份的可信真人颅面，非通用 AI 美人脸、动漫脸贴皮或过度对称商业假脸；
2. 皮肤区域差异和微细节尺度正确，无统一磨皮、统一毛孔、整体发红、蜡状 SSS 或全脸锐化；
3. 头发具有宏观轮廓、不均匀中尺度发组和受镜头限制的稀疏单丝，无条带、根根过锐或整片塑料假发；
4. 身体关节、软组织、承重、重心、压缩和接触成立，九头身未造成缩头、拉腿或构图变化；
5. 服装和饰品具有材料对应的厚度、边缘、缝线、受力、折痕、垂坠、透光和反射；
6. 焦点、景深、运动模糊、曝光、白平衡、亮暗部与轻微成像痕迹一致，人物和环境共享色溢出、反射及接触阴影；
7. 未改变原画身份、发型、服装覆盖、姿势、构图和可见光线，未补全未知、遮挡或画外内容。

任一项失败即为 `FAIL`。保留已通过区域，只修失败字段；最多两次局部修正调用，仍失败则停止并报告，不无限重试。全部通过才是 `PASS`。`PASS` 只表示未发现明确摄影物理、身份或 AI 感失败，不代表图片是真实世界拍摄，也不作“100% 真实照片”的数学保证。

## 备份与恢复

升级前保留当前插件目录副本或记录已安装的 Git 提交。需要回滚时，从备份或先前提交恢复第二步插件，并通过原安装方式重新安装；不直接编辑缓存或替换全局配置。恢复或升级后在新任务中验证调用。结构验证与安装成功不等于实图验证通过。
